# UI kit · 图谱系统

七张真实图谱，每张都是纯数据。左栏切类型，顶栏切变体与明暗，下方展开的就是这张图的输入。

| 图谱类型 | 用什么 | `layout` |
| --- | --- | --- |
| 流程图 | `Diagram` | `layered` |
| 思维导图 | `Diagram` | `tree` |
| 系统架构 | `Diagram` + `groups` | `grid` |
| 人 / Agent / 工具 分工 | `Diagram` + `annotations` | `layered` |
| 对比图 | `Diagram` + 两个 `groups` | `grid` |
| 工作流 | `Diagram` + 回边 | `layered` |
| 时间线 | `Timeline` | — |

## 给 Agent 的生成规则

1. **只产出数据。** `{nodes, edges, groups, annotations}`。不要写坐标，不要写颜色，不要写 SVG。
2. **角色必须从八个里选**：`input` `process` `human` `agent` `tool` `data` `output` `external`。选不出来说明这个节点还没想清楚。
3. **状态只有三个**：`verified` `failed` `unknown`。不确定就 `unknown`，不要省略。
4. **边只有四种**：`flow` 流程 · `data` 数据 · `dep` 依赖 · `weak` 弱关联。回边（打回、重试）照常写，引擎会走下方通道。
5. **一张图不超过 9 个节点。** 超了就拆，或者提一层抽象。
6. **一张图最多两条批注**，每条两行以内。批注自动落在图的外侧留白，不会压到节点；\`side\` 只决定落在左边还是右边。要写更多就写正文。
7. **不确定布局就用 `layered`**，它按依赖自动分层，永远不会重叠。
8. `meta` 写具体的东西：命令、模型名、耗时、环境。写不出来就留空，不要写"高效"。

## 尺寸与渠道

图谱有固有像素尺寸，按容器宽度**等比缩小、永不放大**。

- **小红书卡片**：放进 `<Page>`，栏宽 1050 —— 6 节点以内一张卡放得下，再多就横向拆成两页。
- **公众号**：677 栏宽会缩到约 60%，节点正文 15px 缩完约 9px，**偏小**。公众号里优先用 `Timeline`（它是 flex 布局，reflow 不缩放），或者把大图拆成两三张小图。
- **网站 / 作品集**：原尺寸最佳。
- **GitHub README**：截图导出 PNG。README 不跑 JS，别指望内嵌。

## 已知限制

- 节点尺寸固定不测量文字。**标题超过约 14 个汉字会溢出**——这是刻意的约束，逼你把标签写短。真要长文案就用 `colSpan: 2`。
- `tree` 布局只认一个根，多根时后面的根会顺序堆在下方。
- 回边走线通道只有一条，两条以上回边会叠在一起。
- 暗色下的 `--dg-agent-bg` 用了 `color-mix`，老浏览器会退化成透明。
