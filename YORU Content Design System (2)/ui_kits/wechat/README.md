# UI kit · 公众号排版

和小红书图文台读的是同一个 `content.js`。同样的 block，不同的版式规则 —— 不是把卡片缩小贴进来。

**与卡片版的差异**

| | 小红书卡片 | 公众号文章 |
| --- | --- | --- |
| 列宽 | 1050 px | 677 px（手机 375） |
| 正文 | 40 px / 1.75 | 16 px / 1.85 |
| 分页 | 自动切成 N 页 | 连续滚动，不分页 |
| 标题层级 | 每页一个 H1 | 一个 H1 + 多个 H2 |
| 图片 | 定宽定比，最多一张 | 可连续多张 |
| 结尾 | 独立结尾卡 | 文末署名区 |

**闭环**（跟小红书对齐）：

```
blocks[] → export_wechat.mjs → out/wechat-article.frozen.html → 打开点复制 → 公众号编辑器粘贴 → 后台传图
```

**预览 HTML 不是交付物。** 工作台里的 `index.html` 是给作者本机看排版的——它带 `<style>` 块、
class、CSS 变量，公众号编辑器会把这些全部剥光；粘进去出来的是一大段 HTML 源码文字，不是排好版的稿。
真正能贴的是冻结产物 `out/wechat-article.frozen.html`：正文区每个元素自己扛着行内 `style`，
零 class、零 `var(--)`，文件顶部自带一个「复制到公众号」按钮，任何机器、任何环境打开点一下就成。

**复制机制**：range 选中 + `document.execCommand("copy")`。这条路径同时给剪贴板写
text/plain 与 text/html，公众号编辑器吃后者。`navigator.clipboard.writeText()` 只写 text/plain——
粘进去是源码。`ClipboardItem` 双格式在别的编辑器里更干净，但对公众号编辑器 paste 路径实测不如
execCommand 稳，所以主路径用 execCommand。工作台里的复制按钮同一套。

**已知限制**（都写在这里，不要在别处再猜一遍）：

- 公众号不加载外部字体。中文会落到 PingFang SC / 微软雅黑，等宽会落到系统等宽。版式按这个前提设计过，掉字体不会散。
- `display:flex` 与 `gap` 在部分安卓客户端表现不稳。冻结产物尽量用 block + margin 表达；导出后请在手机上过一遍长表格与步骤列表。
- 代码块导出为深色 `<pre>`，公众号不会做语法高亮，本系统本来也不做。
- 图片需要在公众号后台重新上传，导出的 HTML 只保留占位与图注。冻结产物顶部会有提示条。
