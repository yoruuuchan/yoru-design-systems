# YOZORA 夜空 — rollout notes (integration, 2026-10-08)

Mechanical integration of the approved YOZORA proposal into the Aozora system.
Theme selector: `[data-theme="yozora"]`. Default light theme must stay identical.

## Decisions

1. **D1/D2** — `tokens/yozora.css` is an exact copy of the approved proposal tokens
   (one header line added; diff-verified byte-identical otherwise). Imported as the
   LAST line of `styles.css`.
2. **Component fixes use the fallback-var pattern**: inline styles become
   `var(--aoz-<hook>, <original literal>)` so the light theme computes
   byte-identical values. The hooks are defined only under `[data-theme="yozora"]`
   in a new file `tokens/yozora-overrides.css`, and every hook value references an
   approved token (no new color values invented). The overrides import sits just
   BEFORE `tokens/yozora.css` in `styles.css` (deviation: spec only listed one
   import; the hook file is the "scoped override" mechanism D4 allows, and the
   import-only convention of styles.css forbids plain rules there).
3. **UI kit screens** get the same treatment with kit-scoped hooks defined in a
   `<style>` block inside `ui_kits/app/index.html` (kit concerns stay in the kit;
   all values reference approved yozora tokens). Standalone `ui_kits/app/*.jsx`,
   `app-bundle.jsx` and the inline copy in `index.html` are edited identically
   (three copies of the same code; index.html / app-bundle.jsx are generated by
   concatenation). Home bg → `--gradient-moonrise`, Settings/page bg →
   `--gradient-night`, sheet/sections/pickers → `--surface-elevated`, hardcoded
   neutral ink → `--text-strong`, dark-blue accents → `--text-accent`.
   **Tab bar** uses `--glass-bg-dark` (not thin glass): over the Home screen's
   bright flavor tiles, 7% thin glass washed the tab icons/labels out — verified
   by screenshot. Dark tinted glass is an approved token and keeps the bar
   legible over arbitrary bright content.
4. **`_ds_bundle.js`** is a generated artifact (sourceHashes-tracked) and was
   already stale vs. current component sources before this rollout (its Button
   glass shadow predates the current source). Component edits are mirrored into
   it by hand with its own existing literals as fallbacks, so screenshots
   exercise the fixes; hashes will mismatch and the toolchain should regenerate
   it on next open.
5. **SRI fix in `ui_kits/app/index.html`** (deviation, pre-existing bug): the
   `integrity` attributes for the three vendor scripts did not match the actual
   files in `assets/vendor/`, so React/ReactDOM/Babel were blocked in every
   standards-compliant browser and the kit rendered blank (broken at HEAD, not
   caused by this rollout). Digests updated to the files' real SHA-384
   (openssl-verified). The five `components/*/*.card.html` have the same
   mismatch — left as-is, flagged for the lead (used by the DS viewer).
6. Approved proposal ambiguities resolved per proposal README's own reasoning:
   `--glass-bg-sun` name kept (file already carries the alias); ember gradient
   kept (it is in the approved tokens).
7. **D5 toggle**: plain-JS bootstrap before `</body>` — `?theme=yozora|default`
   wins and persists to `localStorage["aozora-theme"]`, otherwise restores;
   floating glass pill (bottom-right, z-index 9999, `--glass-*` chrome, 11px)
   flips theme + persists, label shows the target theme. Verified:
   `?theme=default` screenshot is byte-identical to the no-param default shot.

## Deviations from spec

- Extra import `tokens/yozora-overrides.css` (before yozora.css) — the scoped-override
  carrier; `styles.css` convention ("@import lines only") wins over adding plain rules.
- `_ds_bundle.js` hand-mirrored (see Decision 4).
- SRI digests fixed in `ui_kits/app/index.html` (see Decision 5) — without this the
  kit cannot render at all; the same mismatch in the 5 component `*.card.html`
  files was NOT fixed (flagged).
- UI kit screens needed theme hooks for D7(b) to render dark — done via
  kit-scoped hooks in `ui_kits/app/index.html` `<style>` (light stays identical).
- Tab bar night tier is `--glass-bg-dark`, chosen after screenshot review
  (thin glass was illegible over bright tiles).

## Open questions

- Home screen decorations (`glass-blob.svg`, `droplets.svg` at 0.5–0.55 opacity)
  glow bright at night; the approved demo has a calmer sky. Dimming them needs an
  approved opacity value — not improvised.
- Switch off-track (`--neutral-300`) and Dialog/Button bespoke blurs were left
  as-is; if the night look wants them tuned, that needs new approved values.
- Badge/Tag `accent` soft text maps to `--moon-300`; `--glass-bg-sun` alias kept
  (proposal's own open question — alias kept for compatibility).
- Toggle click behavior verified by code path + both URL-param states; the click
  itself was not exercised headless.
